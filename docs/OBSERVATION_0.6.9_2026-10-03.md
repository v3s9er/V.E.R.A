# 0.6.9 프로젝트 지식 작업 검사 — 2026-10-03

## 무엇을 비교했나

설치된 Windows 앱의 인증된 `chat.start`로 실행했다. 모델은 양쪽 모두
**gpt-6-sol**, 선택 추론 medium, Daybreak 꺼짐, full 권한, quality 질문 예산,
단일 실행이다. 모델을 직접 호출하거나 별도 AgentLoop를 구성한 점수가 아니다.
구독 CLI의 실제 모델 목록에서 정확한 모델 사용 가능 여부를 먼저 확인했다.
전역 공급자/모델, Discord 사용자 권한, 모바일 기기 상한은 변경하지 않았다.
로컬 기본 safety.mode는 시작부터 full이었으며 유지했다.

합성 npm 프로젝트 하나에서 store → api/worker → site의 직접·간접 의존 관계,
무관한 docs 패키지, 상대 경로를 사용했다. 두 개의 새 대화에서 각각 아래의
네 요청을 순서대로 실행했다. 중간에는 검사 프로그램이 site의 의존 선언을
실제로 제거했다. 이 파일은 검사 소유 fixture이며 사용자의 프로젝트가 아니다.

1. store 변경의 영향 패키지와 상대 폴더
2. “그거 바꾸기 전에…” 후속 질문과 간접 경로
3. manifest 변경 뒤 현재 영향 범위 재확인
4. 짧은 감사 인사

양쪽 모두 동일한 파일·질문·권한에 접근할 수 있었다. 개선판만 답을 미리
저장한 것은 아니다. 자동 수집한 원본 선언에서 관계를 도출해 문맥에 넣는다.
3개 업무 유형의 반복 6건이지 독립된 외부 대회 문제 6개가 아니다. 순차 검사로
네트워크·공급자 부하·캐시를 통제하지 않았고, 온톨로지 단독의 인과 효과나
다른 작업으로 일반화되는 성능 향상을 입증하지 않는다.

## 실제 지식 사용과 정답

- 영향/후속 요청: 각 실행에서 사실 **14**, 추론 **1**, 충돌 **0**, 문맥 약 **5.6 KB**가 주입됐다.
- 선언을 바꾼 뒤: 사실 **13**, 추론 **0**, 문맥 약 **5.0 KB**로 갱신됐다. 제거된 간접 의존 경로를 답에 그대로 재사용하지 않았다.
- 인사: 사실·추론·지식 문맥 **0**, 도구 **0**. 모든 요청에 온톨로지 문맥을 붙이지 않는다.
- 업무 6건은 변경 전·중간판·최종 지침판 모두 맞았다. docs를 영향에서 제외하고 수정 뒤 site도 제외했다. **정확도 상승은 입증되지 않았다.**
- 최종 지침판의 업무/인사 8건 모두 모델 식별·최종 결과·스트림 일치 검사를 통과했다.

## 관측한 시간과 사용량

각 셀은 두 실행의 관측값을 모두 적었다. 시간은 앱 요청부터 완료까지 초,
토큰은 공급자가 보고한 입력+출력 합계이며 캐시 입력도 포함한다. 비용 절감액은
계산하지 않았다. 짧은 후속 질문에도 지식 문맥을 넣으면 토큰이 늘 수 있다.

| 요청 | 0.6.8 완료 시간 | 0.6.9 최종 지침판 | 0.6.8 토큰 | 0.6.9 토큰 | 도구 수 전 → 후 |
| --- | --- | --- | --- | --- | --- |
| 영향 패키지 조회 | 28.796 / 28.250 | 7.321 / 8.266 | 39,760 / 39,765 | 15,179 / 15,198 | 2 / 2 → 0 / 0 |
| 지시어 후속 질문 | 12.826 / 10.558 | 10.466 / 9.481 | 11,765 / 11,645 | 13,907 / 13,927 | 0 / 0 → 0 / 0 |
| 선언 변경 재확인 | 26.933 / 25.435 | 22.105 / 27.724 | 36,863 / 36,567 | 32,584 / 49,253 | 2 / 2 → 1 / 2 |
| 감사 인사 | 3.828 / 실패 6.629 | 4.034 / 2.945 | 3,808 / 미보고 | 3,850 / 3,863 | 0 / 0 → 0 / 0 |

영향 조회의 첫 출력도 25.582 / 25.053초에서 4.126 / 4.389초로 줄었다.
그러나 선언 변경 재확인의 두 번째 실행은 더 느리고 토큰도 늘었다. 따라서
**원본 선언이 충분한 조회에서 중복 읽기를 줄인 것은 관측했지만, 모든 작업이
더 빠르거나 더 저렴해진 것은 아니다.**

## 중간 실패와 조정도 보존

- 첫 전체 검사에서 서버/모바일 버전 상수가 구버전인 일치 검사 실패를 발견해 모두 0.6.9로 맞췄다. 최종 전체 검사는 통과했다.
- 첫 개선판의 영향 조회는 19.882 / 16.629초, 도구 7 / 1회, 토큰 47,202 / 30,400이었다. 이미 호스트가 읽은 선언을 모델이 다시 확인했다. “선언만 묻는 읽기 전용 조회는 충분한 현재 근거로 답하고, 실제 수정 직전·충돌·변경 이후는 재확인”하도록 지침을 구분했다. 검증을 일괄 생략하거나 도구를 강제로 막지 않았다.
- 변경 전 인사 1건은 부분 답변 뒤 `구독 메시지 순서 불일치`로 실패했다. 미보고 토큰을 0 사용량으로 세지 않았으며, 안전 예산 예약 15,636을 실제 토큰으로 합산하지 않았다. 개선판 인사에서는 재발하지 않았지만 이번 변경이 그 간헐 오류를 해결했다고 주장하지 않는다. 스트림 검증을 느슨하게 바꾸지 않았다.
- 최초 실도구 확인 스크립트는 원시 도구 이름을 기대했으나 공개 이벤트는 안전하게 `native_host_tool`로 일반화되어 있어 확인 실패로 남았다. 지식 조회 중인데 “PC 화면 확인 중”으로 표시되는 기존 일반 라벨도 발견했다. 지식 전용 상태를 추가한 뒤 실도구 검사를 통과했다. 호스트의 “프로젝트 지식 조회 중” 상태, 일반화된 도구 시작/종료, 동일 gpt-6-sol 결과를 확인했다. 이 마지막 변경은 표시·관측만 바꾸며 위 모델 측정의 지침은 바꾸지 않는다.

원시 보고서·실패 로그·검사 대화 식별자·로컬 연결 정보는 공개 Git이 아닌
`release/validation`에 보존한다. 검사 대화 8개만 보관 처리하고 검사 프로젝트의
등록만 해제했다. 실제 파일과 기록은 삭제하지 않았다.

## 검사 범위

- 전체 `npm test` 통과: 원격 연결, Discord 격리·모델 정책·파일, UI 계약, 저장 복구, 네이티브 세션, 조율, 튜닝, 온톨로지 및 기존 회귀 포함.
- 최종 지침 조정 뒤 전체 TypeScript 검사와 적응형/온톨로지 검사, 원격 보안 검사 통과. 마지막 링크/개수 경계 추가까지 새 프로젝트 지식·실행 연결 검사 11개 통과.
- 마지막 상태 라벨 수정 뒤 네이티브 풀 및 세션 회귀 28개 통과. 설치 앱의 `memory.inspect`에서도 현재 선언 13개와 의존 관계를 확인했다.
- 새 검사: 선언 갱신, 범위 격리, 사용자 주장 충돌, 지시어 후속/주제 변경, 미지원 glob·경로 이탈·junction·hardlink·과대/손상 파일·64개 상한, 조회 인수·횟수 제한, API/네이티브 연결, Discord 차단, 인사 경량 경로.
- 공개 소스 및 도달 가능한 Git 이력의 알려진 토큰/개인 상태/서명 자료 검사, `git diff --check` 수행. 모든 비밀의 부재나 앱 무결함을 보증하는 검사는 아니다.

범용 문서 자동 지식화, 모델 학습, 온톨로지 기반 런타임 정합성 증명은 이번
구현 범위가 아니다. 자동 그래프는 npm 선언 기반이며 기타 일반 지식은 기존
명시적 저장을 사용한다. 온톨로지 엔진의 출처·충돌·권한 경계는 유지한다.
