# Sol 재평가와 미실행 항목 상태 — 2026-09-23

## 결론

**Sol로 유효한 성능 평가를 시작하지 못했다. 점수 향상이나 전체 평가 완료를 주장하지 않는다.**
요청 모델은 `gpt-5.6-sol`로 유지했고 Terra 등으로 대체하지 않았다.

설치 CLI `0.153.4`의 `model/list`는 `gpt-5.6-terra`, `gpt-5.6-luna`, `gpt-5.5`를 반환했다.
첫 BFCL 접근 확인은 첫 문항의 실행 오류에서 중단됐다. 기준 완료 0개, 후보 미실행이므로 정확도 0점이라는 성능 결과로 해석하면 안 된다.
원본 오류를 노출하지 않는 분류를 추가한 뒤, 공식 npm 패키지 `@openai/codex@0.156.1`을 임시 폴더에 설치해 재확인했다.
이 설치는 기존 전역 CLI나 앱 설정을 덮어쓰지 않았고 설치 스크립트를 실행하지 않았다.

`0.156.1`의 모델 목록은 `gpt-6-luna`, `gpt-5.6-terra`, `gpt-5.6-luna`, `gpt-5.5`였고 Sol 호출은 `model_unavailable`로 거절됐다.
따라서 이번 환경에서 단순 CLI 버전 교체만으로 해결되지는 않았다. 원인을 계정 정책의 특정 내부 규칙으로 단정하지는 않는다.
Sol 사용이 가능한 CLI 계정/연결을 마련한 뒤 같은 모델명으로 재확인해야 한다.
공식 [Sol 모델 설명](https://developers.openai.com/api/docs/models/gpt-5.6-sol)의 API 지원 정보가 이 CLI 계정의 사용 권한을 보장하지는 않는다.

## 이번에 수정한 실행 경로

- 모델 목록에 요청한 모델이 없으면 평가를 시작하기 전에 중단한다. 다른 모델로 자동 대체하지 않는다.
- 구독 브로커의 실패를 모델 접근·인증·사용량·문맥 한도로 구분하고, 원격 오류 원문/경로/자격증명은 출력하지 않는다.
- 실행 도중 접근이 거절되면 실패 유형을 보존하고 나머지 모델 요청을 중단한다.
- 미완료 보고서에는 모델 능력 점수로 해석하지 말라는 경고를 표시한다.
- 기존 문항의 정답, 채점 기준, 과거 결과는 수정하지 않았다.

이는 실패 진단과 불필요한 실행 방지 개선이다. 아직 Sol 정확도·지연 개선 증거는 아니다.

WSL에는 Ubuntu 24.04와 Docker Desktop 배포판이 등록되어 있다. 등록은 엔진 실행이나 평가 준비 완료를 의미하지 않는다.
검사 당시 호스트 메모리는 약 32GiB, 여유 메모리는 약 10GiB, C 드라이브 여유 공간은 약 613GiB였다. 이 수치는 현재 환경의 일시적인 측정이다.
Docker 서비스·VM·기존 작업은 시작/종료하지 않았고, 사용자 폴더·인증정보를 평가 환경에 마운트하지 않았다.
유료 API 결제나 모델 가중치 다운로드, 리더보드 제출, 설치 앱 교체를 하지 않았다.

## 정확도 개선 실험 순서

1. Sol 접근부터 검증한다. 실행 실패는 오답과 분리해 해석한다.
2. 같은 Sol·추론 설정에서 일반화 가능한 도구 설명/문맥/인자 검증 개선을 한 항목씩 비교한다.
3. 도구를 호출하지 않아야 하는 문제, 여러 호출을 모두 수행해야 하는 문제, 인자 형식·의미 오류를 각각 집계한다.
4. 알려진 정답을 프롬프트에 넣거나 실패 문항을 제거하지 않는다. 개발 문제에 맞춘 수정은 미사용 보류 문제로 따로 검증한다.
5. 품질·응답시간·토큰을 함께 확인한 뒤에만 실제 앱 설정을 변경한다. 모든 문제의 정확도가 반드시 오른다고 보장하지 않는다.
