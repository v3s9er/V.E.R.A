# Mr.Robot 적응형 협업 최적화 평가

0.6.12의 네 문제 검사에서 고정 순차 혼합 구성이 Astra 단일 실행보다 더 느리고 정확하지 않았습니다. 이번 변경은 호출 수를 무조건 늘리는 대신, 최종 모델이 필요한 증거를 기준으로 보조 작업을 선택하도록 합니다. 논문의 결과를 앱 성능 수치로 대체하지 않으며, 구조 검사와 실제 모델 검사를 구분합니다.

## 연구 근거와 적용 범위

[Towards a Science of Scaling Agent Systems](https://arxiv.org/abs/2512.08296v3)는 여러 과제와 실행 구성을 통제 비교하며 작업 분해 가능성과 구조의 적합성이 중요함을 보여줍니다. 복잡하다는 이유만으로 모든 요청을 다중 모델 토론에 보내는 정책의 근거로 쓰지 않았습니다. 여기서 도출한 앱 설계 선택은 최종 모델 우선 실행과 선택적 독립 조사입니다. 논문 실험을 재현한 구현이라는 뜻은 아닙니다.

[AgentDropout](https://aclanthology.org/2025.acl-long.1170/)은 불필요한 노드와 통신을 줄이는 학습 기반 그래프 최적화를 연구합니다. 이번에는 학습된 그래프나 논문의 알고리즘을 복제하지 않았습니다. 중복 질문·동일 제안 제거, 변하지 않는 토론의 종료라는 보수적인 휴리스틱만 구현했습니다. 논문의 절감률을 우리 앱에 그대로 적용하지 않습니다.

[Large Language Models Cannot Self-Correct Reasoning Yet](https://arxiv.org/abs/2310.01798v2)는 외부 피드백 없는 자기 수정의 한계를 분석한 ICLR 2024 연구입니다. 과거 모델에 대한 결과이므로 현재 모델의 능력 한계로 일반화하지 않습니다. 앱 지침에는 자신감이나 다수결보다 실제 계산·테스트·재현을 우선하도록 반영했습니다. 형식 검사 통과만으로 의미적 정답을 보증하지 않습니다. 모든 자유형 답변을 자동 판정하는 검증기를 새로 만든 것은 아닙니다.

[OpenAI 공식 지연 최적화 지침](https://developers.openai.com/api/docs/guides/latency-optimization)의 중복 입력과 순차 호출 감소 원칙을 적용했습니다. [평가 지침](https://developers.openai.com/api/docs/guides/evaluation-best-practices)에 따라 모델 선택과 중간 전달까지 검사하고, 실패 요청을 결과에서 제외하지 않습니다.

## 구현과 안전 경계

새 실행 방식은 고정된 4회 호출 대신 주 모델 1회로 시작합니다. 등록된 보조 모델이 있어도 자동으로 전부 호출하지 않습니다. 보조 모델은 별도 문맥에서 주어진 부분만 분석하고 선택 작업 폴더의 읽기 도구만 사용할 수 있습니다. 쉘·파일 변경·데스크톱·플러그인·재귀 위임은 빌려주지 않습니다. 주 모델의 권한, 호출 예산, 취소는 그대로 유지됩니다.

선택한 모델이 없으면 다른 모델로 바꿔 성공처럼 보이게 하지 않습니다. 격리된 Discord 실행에는 호스트 협업 도구를 넣지 않습니다. 단일 모델의 기본값을 새 정책으로 자동 변경하지 않습니다. 온톨로지의 사실 추론이나 모델 가중치를 새로 학습한 작업도 아닙니다.

순차 파이프라인은 원래 질문을 한 번만 전달합니다. 보조 제안은 18,000바이트 안에서 명시적으로 축약하며 동일 문자열을 중복 전달하지 않습니다. 원래 질문과 보존 문맥은 이 제안 예산에 넣지 않으므로 질문 앞부분이 잘리지 않습니다. 전체 모델 문맥 한도가 없어졌다는 의미는 아닙니다.

## 검사 조건

정적·회귀 검사와 실제 Electron 렌더링·복구 검사를 실행합니다. 별도 임시 앱 데이터와 실제 데스크톱 렌더러의 인증된 로컬 IPC를 사용하여 `chat.start`에 요청합니다. 독립 CLI에 문제만 직접 보내는 검사가 아닙니다. 생산 앱의 사용자 대화, 플러그인, 네트워크 설정은 검사에 복사하지 않습니다.

모델은 최종 `gpt-6-astra`, 고정 순차의 중간 단계는 Astra → `gpt-6.1-sol` → `gpt-6-luna`입니다. 적응형은 같은 그래프의 마지막 Astra부터 실행하고 보조 호출은 필요할 때만 선택합니다. 모든 본 문제는 high, Daybreak 끔, 읽기 전용, 감사 전용 토큰 정책, 요청당 600초 한도를 사용합니다.

개발 회귀 문제는 이전에 측정한 공개 ARC-AGI-2의 `3dc255db`와 `2c181942`입니다. 한 문제는 단일 → 순차 → 적응형, 다른 문제는 적응형 → 순차 → 단일 순서로 각각 한 번씩 실행합니다. 이번에는 모든 조건에 제한된 로컬 계산과 검증을 허용하므로 이전의 도구 금지 실험과 수치를 직접 전후 비교하지 않습니다. 정답은 외부 채점기에만 있으며 모델에는 예제와 테스트 입력만 제공합니다. 모델에게 정답 키를 조회하거나 다른 파일·대화·네트워크를 이용하지 않도록 지시합니다. OS 차원의 완전한 네트워크 격리 실험은 아닙니다.

원시 답변은 테스트 출력의 순서·개수·모든 셀·직사각형 형식이 모두 맞아야 통과입니다. 출력 오류를 임의로 보정하거나 실패한 답변을 재실행하여 바꾸지 않습니다. 같은 문항을 개발 과정에서 이미 확인했으므로 새로운 문제에 대한 일반화나 공식 ARC Prize 점수를 주장할 수 없습니다. 두 문제의 한 번 측정으로 통계적 우열도 주장하지 않습니다.

토큰은 공급자가 보고한 입력과 출력 합계입니다. 캐시 입력을 포함하며 실제 구독 사용량 차감이나 요금은 아닙니다. 주 모델 내부의 도구 단계는 한 번의 최종 모델 호출에도 여러 내부 추론 요청을 만들 수 있습니다. 따라서 논리적 호출 수만으로 토큰 절감을 계산하지 않습니다.

## 구현 검사 결과

- 전체 `npm test`와 후속 회귀 검사를 통과했습니다. 최초 실행의 프리셋 개수 검사는 새 프리셋을 반영하지 않은 기대값 11 때문에 실패했고, 12로 고친 뒤 전체 검사를 다시 통과했습니다.
- 에이전트·웹·모바일 타입 검사, 적응형의 모델 선택·격리·예산·취소·실패 처리 검사, 기존 순차·회의 회귀 검사를 통과했습니다.
- 실제 Electron 창에서 입력창 렌더링과 렌더러 강제 종료 후 복구를 확인했습니다. 모델 평가는 별도 임시 데이터로 실행하여 기존 앱 대화를 변경하지 않았습니다.
- 공개 배포 위생 검사와 알려진 로컬 자격증명의 소스·Git 이력·PC 패키지 내 일치 검사를 통과했습니다. 알려지지 않은 비밀 정보까지 부재를 보증하는 검사는 아니며 APK는 검사 대상이 아닙니다.
- Windows 0.6.13 설치 파일을 생성했습니다. Authenticode 상태는 `NotSigned`이며 코드 서명된 배포물이라고 주장하지 않습니다.

## 실제 앱 평가 결과

두 문항에서 세 방식 모두 정답 및 전달 프로토콜 검사를 통과했습니다. 시간은 요청부터 응답 저장까지의 벽시계 시간이며 아래 합계는 각 방식의 두 요청 합계입니다.

| 방식 | 정답 | 합산 시간 | 보고 토큰 합계 |
|---|---:|---:|---:|
| Astra 단일 | 2/2 | 203.173초 | 77,980 |
| Astra → Sol 6.1 → Luna → Astra 순차 | 2/2 | 604.017초 | 110,048 |
| Astra 적응형 | 2/2 | 233.635초 | 79,827 |

| 문항 | 방식 | 시간 | 보고 토큰 | 정답/프로토콜 |
|---|---|---:|---:|---|
| `3dc255db` | 단일 | 57.820초 | 27,463 | 통과/통과 |
| `3dc255db` | 순차 | 222.464초 | 34,324 | 통과/통과 |
| `3dc255db` | 적응형 | 80.071초 | 28,728 | 통과/통과 |
| `2c181942` | 적응형 | 153.564초 | 51,099 | 통과/통과 |
| `2c181942` | 순차 | 381.553초 | 75,724 | 통과/통과 |
| `2c181942` | 단일 | 145.353초 | 50,517 | 통과/통과 |

이번 표본에서 적응형은 순차 대비 합산 시간이 **61.3%**, 보고 토큰이 **27.5%** 적었습니다. 그러나 단일 대비로는 시간이 **15.0%**, 토큰이 **2.4%** 더 들었습니다. 그러므로 적응형이 단일보다 빠르거나 정확하다고 결론 내릴 수 없습니다. 기본 단일 실행은 유지하며, 항상 다중 모델을 호출하던 사용자를 위한 선택 대안으로 제공합니다.

본 문제의 적응형은 모두 보조 모델이나 계산 도구를 호출하지 않았습니다. 이 결과는 불필요한 순차 단계를 생략한 효율을 보여줄 뿐, 여러 모델의 공동 추론으로 정확도가 높아졌다는 증거가 아닙니다. 순차 실행은 두 요청 모두 Astra·Sol 6.1·Luna 단계를 거쳤으며 단계 실패나 시간 초과는 없었습니다. 최종 모델은 모든 조건에서 Astra/high였고, 스트림·저장 답변·최종 응답이 일치했습니다. 검사 종료 후 실행 중 요청은 0개였습니다.

별도의 보조 연결 검사에서는 Astra가 등록된 `solve` 작업자를 호출했고, 실제 `gpt-6.1-sol` 작업 완료 및 사용량을 관측했습니다. 전체 14.297초·36,939토큰 중 보조 모델 보고량은 3,508토큰이었습니다. 이 검사는 라우팅 검증용으로 일부러 쉬운 산술에 위임을 요구했으며 본 문제의 성능 표에 포함하지 않았습니다. 사소한 작업에 위임을 강제하면 안 된다는 비용 사례이지 속도 향상의 증거가 아닙니다.

이전 `2c181942`의 잘못된 격자 길이는 이번 검사에서는 재현되지 않았습니다. 하지만 도구 허용 지침과 실행 조건이 바뀌었고 단회 결과이므로, 해당 오류가 영구히 해결됐거나 일반 정확도가 향상됐다고 주장하지 않습니다. 다음 정확도 검증은 사용하지 않은 문제와 반복 실행, 동일 계산 예산의 비교가 필요합니다.

## 로컬 설치 확인

기존 PC 앱에 0.6.13을 설치하고 다시 실행했습니다. 인증된 로컬 RPC에서 버전 0.6.13, 실행 중 요청 0개, 새 적응형 프리셋을 확인했습니다. 설치된 `app.asar`와 빌드 산출물의 SHA-256은 일치했습니다. 평가에 사용한 에이전트 번들도 최종 재빌드와 동일했습니다. 기존 공급자·기본 실행 방식에 대한 설정 변경 요청은 보내지 않았습니다. GitHub Release 바이너리나 모바일 APK 업로드는 이번 검증에 포함하지 않습니다.
