# Mr.Robot 0.6.12 혼합 모델 ARC-AGI-2 평가

설치된 Mr.Robot의 공통 실행 엔진으로 ARC Prize 공개 문제 4개를 네 조건에서 총 16회 측정했습니다. 이번 순차 혼합 구성은 단일 Astra보다 정확도가 높지 않았고 더 느렸습니다. MD 지침과 온톨로지를 추가한 구성도 기본값으로 승격하지 않았습니다. 실행 경로 오류는 수정했지만, 이 측정으로 정확도 향상을 입증하지는 못했습니다.

## 문제와 실행 조건

[ARC Prize의 ARC-AGI-2](https://arcprize.org/arc-agi/2)는 예제 격자에서 변환 규칙을 찾아 새 입력에 적용하는 평가입니다. 공식 [데이터 저장소](https://github.com/arcprize/ARC-AGI-2) 공개 평가 문제 120개 중 4개를 결과 확인 전에 고정했습니다. 저장소 리비전은 `f3283f727488ad98fe575ea6a5ac981e4a188e49`입니다.

선택은 `MrRobot-20261003-ARC2-mixed-v1`과 각 파일 경로를 콜론으로 연결한 SHA-256의 오름차순 앞 4개입니다. 문제는 `88bcf3b4`, `3dc255db`, `2c181942`, `38007db0`이며, 테스트 정답 격자는 합계 6개입니다. 정답은 외부 채점기에만 남기고, 모델에는 학습 예제의 입력·출력과 테스트 입력만 전달했습니다.

| 조건 | 실제 모델 실행 | 추가 프로젝트 문맥 |
| --- | --- | --- |
| 단일 | Astra | 없음 |
| 혼합 | Astra 계획 → Sol 6.1 풀이 → Luna 반례 검토 → Astra 최종 판단 | 없음 |
| 혼합과 MD | 위와 동일 | AGENTS.md |
| 혼합과 MD 및 온톨로지 | 위와 동일 | 같은 AGENTS.md와 범위 제한 지식 그래프 |

정확한 모델명은 `gpt-6-astra`, `gpt-6.1-sol`, `gpt-6-luna`입니다. 모두 연결된 Codex 구독 경로에서 사전 실호출이 성공했습니다. Claude는 목록에 표시됐지만 실호출이 실패하여 포함하지 않았습니다. 사용 불가를 오답으로 처리하거나 다른 모델로 몰래 대체하지 않았습니다. 혼합 조건은 의존 관계를 따른 순차 파이프라인이며 병렬 실행이나 공급자 간 비교가 아닙니다.

- 인증된 설치 앱의 `chat.start`로 직접 요청했습니다. 앱 UI와 같은 중앙 실행 엔진이지만 화면 조작, Discord 전송, 모바일 네트워크 지연을 측정한 것은 아닙니다.
- 전 조건 `high`, Daybreak 끔, 읽기 전용, 사용량 감사 전용 정책입니다. 같은 전체 요청 제한 600초, 조건별 문제당 한 번, 재시도 없음입니다. 조건 순서를 문제마다 순환했습니다.
- 시간은 `chat.start` 요청부터 응답 완료까지입니다. 검사 프로젝트 생성과 온톨로지 사실 사전 등록 시간은 포함하지 않지만, 요청 중 지식 조회와 모델 호출 시간은 포함합니다.
- 도구 실행 없이 문자 격자를 추론하는 검사입니다. 도구 사용은 프롬프트에서 금지했고 실제 도구 호출이 있으면 프로토콜 위반으로 분리합니다. OS 수준으로 파일·네트워크가 차단된 평가라는 뜻은 아닙니다.
- 최종 격자의 개수·순서·크기·모든 셀이 정확해야 정답입니다. 한 문제에 테스트가 두 개면 모두 맞아야 그 문제를 통과합니다. 채점 모델이나 부분 정답을 완전 정답으로 인정하는 판단은 쓰지 않습니다.
- 단계별 실제 모델 상태, 텍스트 단계 3회와 네이티브 최종 단계 1회, 최종 Astra 경로, 저장 답변과 스트림 일치도 확인합니다. 단일 조건은 선택 모델 1회 완료를 확인합니다.

## MD와 온톨로지의 범위

AGENTS.md는 계획·풀이·반례 검토·최종 확인 역할별 일반 지침입니다. 여러 가설이 가능하면 예제 전체에서 검증하고, 모순을 확인하며, 최종 형식을 검사하도록 합니다. 특정 문제의 규칙이나 정답은 넣지 않았습니다. 두 MD 조건의 파일 내용은 같습니다.

모든 조건에 동일한 격자 크기, 색상별 개수, 예제·격자 소속 관계를 평문으로 전달합니다. 온톨로지 조건만 같은 사실을 해당 프로젝트와 대화 범위에 저장하여 앱의 `is_a`, `subclass_of`, `part_of` 추론을 사용합니다. 이는 물체 분할이나 변환 프로그램을 알아낸 정답 지식 그래프가 아닙니다. 추론된 사실과 주입 문맥의 크기·절단 여부를 실제 계측합니다.

검사가 끝난 후 임시 지식과 프리셋, 프로젝트 등록을 제거하고 검사 대화를 보관 처리했습니다. 사용자 기본 라우팅, 공급자, 플러그인 및 기존 지식이 변경되지 않았음을 비교했고, 남은 실행 작업은 0개였습니다. 평가 질문·정답·원시 응답·인증 보조 파일은 Git에서 제외한 로컬 검증 폴더에만 보존합니다.

MD 조건은 첫 문제의 최종 답이 맞았어도 Sol 단계가 시간 초과하여 완주 정답에는 포함하지 않습니다. 온톨로지 조건도 첫 문제에서 같은 단계 시간 초과가 있었고, 최종 두 격자 중 하나가 틀렸습니다. 모델 단계 완주 자체는 단일과 혼합 각 4/4, MD와 온톨로지 각 3/4입니다. 실패한 요청의 시간도 중앙값과 평균에서 제외하지 않았습니다.

일반 혼합은 단일보다 완료 시간 중앙값이 4.79배, 보고 토큰이 2.96배였습니다. 평균 완료 시간은 조건 순서대로 95.574, 247.012, 275.775, 274.886초입니다. 첫 최종 답변 텍스트 수신 중앙값은 41.832, 212.858, 203.239, 209.663초였으며 단계 진행 상태가 표시되는 시각과는 다릅니다.

토큰은 캐시 입력을 포함한 공급자 보고 입력·출력의 합계이지 실제 구독 차감량이나 요금이 아닙니다. 캐시 입력 보고 합계는 같은 순서로 0, 28,416, 37,632, 1,792입니다. MD와 온톨로지는 중단된 호출의 사용량이 완전히 보고되지 않았을 수 있으므로, 더 적은 숫자를 비용 절감으로 해석하지 않습니다. 캐시와 서버 부하를 통제한 반복 측정도 아닙니다.

세 번째 문제에서 혼합과 MD의 최종 출력은 완전히 같았습니다. 정답은 24×26 직사각형인데 두 출력 모두 한 줄만 27칸이었습니다. 이를 임의로 잘라 정답으로 처리하지 않았습니다. 온톨로지 조건은 이 문제를 맞혔지만 첫 문제를 틀렸으므로, 해당 구성의 종합 정확도가 단일보다 좋아지지는 않았습니다. 이 한 번의 차이만으로 온톨로지의 인과 효과를 주장하지 않습니다.

온톨로지 조건의 실제 사실/추론 관계 수는 문제 순서대로 58/37, 35/22, 35/22, 31/19이며 충돌은 모두 0이었습니다. 주입 문맥은 6,919~6,946바이트로 네 요청 모두 상한에 의해 절단됐습니다. 모든 원래 격자와 동일한 평문 관측 사실은 별도 사용자 입력에 남아 있습니다. 그래프 조회 시간은 1.363~4.895밀리초였으며, 일반 혼합 첫 요청은 총 388.060초 중 약 387.914초가 모델 호출 구간이었습니다. 이 사례에서 주된 대기는 그래프 조회보다 순차 모델 호출에 있었습니다.

16개 최종 응답 모두 선택된 Astra 및 high 경로, 저장 답변과 실시간 스트림 일치, 도구 호출 0회를 확인했습니다. 두 번의 단계 시간 초과는 숨기지 않았으며 전체 요청 600초 제한에 걸린 사례는 없었습니다. 새로운 정답을 얻기 위해 문제를 재시도하거나 모델을 교체한 경우도 없습니다.

이 결과는 모델 수를 늘리거나 일반 관계 그래프를 추가하는 것만으로 정답률과 효율이 자동으로 개선되지 않음을 보여주는 작은 사례입니다. 다음 개선 후보는 실패 단계를 명시적으로 관리하는 실행 예산, 작업별 기계적 결과 검증, 필요할 때만 추가 모델을 호출하는 정책입니다. 아직 적용하거나 효과를 측정한 개선으로 보고하지 않습니다.

## 사전 검사에서 발견한 실행 오류

대회 문제를 시작하기 전의 항등 변환 예제에서 두 번 중단했습니다. 정답 문자열은 맞았지만 최종 모델이 Astra가 아니라 API 도구 실행 공급자로 바뀌었습니다. 첫 검사에서는 전송 경로 기대값 문제로 의심했으나, 재검사와 코드 확인으로 앱 라우팅 결함을 확인했습니다. 이 시도들을 대회 점수에 포함하지 않습니다.

0.6.12는 네이티브 실행이 가능한 마지막 파이프라인 모델을 보존합니다. 새 회귀 검사 4개 중 수정 전 3개가 실패하고 수정 후 4개가 통과했습니다. 기존 council 및 모델 튜닝 loop 검사까지 합친 집중 검사 33개도 통과했습니다. 새 설치본의 같은 예제는 실제 3개 텍스트 단계와 Astra 네이티브 최종 단계를 지나 통과했으며, 그 후에만 본 문제 측정을 시작했습니다.

## 측정 중 발견한 단계 시간 제한

첫 문제의 MD 조건에서 Sol 6.1 텍스트 단계가 내부 제한 180초에 걸렸습니다. 일부 출력이 시작된 뒤 완료되지 못했고, 앱은 실패 안내를 다음 단계로 전달하여 Luna와 최종 Astra를 계속 실행했습니다. 최종 격자는 맞았지만 세 중간 단계 중 두 개만 정상 완료했으므로, 요청한 혼합 구성의 성공으로 인정하지 않았습니다.

검사기는 이 불일치를 감지해 먼저 중단했습니다. 원인을 확인한 뒤 중단 규칙만 좁게 보완하여, 확인된 180초 단계 시간 초과는 실패 기록을 유지하고 나머지 요청을 수행하도록 했습니다. 최초 세 요청을 재시도하거나 교체하지 않았고, 앱 코드·모델·프롬프트·MD·지식 구성·채점·순서·시간 제한은 바꾸지 않았습니다. 이전 보고서의 해시를 후속 보고서에 연결했습니다. 따라서 완전히 중단 없이 끝난 사전 등록 실험이 아니라, 이 절차 보완을 공개한 탐색 검사입니다.

## 검사 범위와 해석 제한

- 전체 `npm test`와 후속 회귀, agent·web·mobile 타입 검사를 통과했습니다. 첫 전체 검사의 실패는 빠진 런타임 버전 상수 동기화였으며 이를 수정하고 전체를 다시 통과했습니다.
- 실제 Electron stage에서 입력창 표시, 렌더러 충돌 복구 및 에이전트 PID 유지 검사에 통과했습니다. 사용자 앱의 활성 작업 0개 확인 후 설치 프로그램 종료 코드 0, 설치와 빌드 `app.asar` 일치, 0.6.12 실행을 확인했습니다.
- 알려진 자격증명 11개를 값 출력 없이 소스 index·도달 가능한 이력·데스크톱 stage의 965개 검사 표면과 대조했으며 일치가 없었습니다. 미지의 비밀이나 짧은 PIN까지 없다는 보장은 아닙니다.
- 공개 문제 4개, 조건별 한 번인 탐색 검사입니다. 공식 전체 대회 점수나 비공개 평가, 통계적으로 입증된 우열이 아닙니다. 공개 문제의 사전 학습 포함 가능성도 배제할 수 없습니다.
- 공식 대회와 달리 한 번만 제출하는 pass@1이며, 도구로 프로그램을 실행하는 ARC 시스템을 평가한 것도 아닙니다. 혼합은 단일보다 호출 수와 사용 모델이 다르므로 같은 계산량 비교가 아닙니다.
- MD의 효과는 혼합 대비 MD 추가, 온톨로지의 효과는 같은 MD 위에 그래프 추가로만 비교합니다. MD 단독·온톨로지 단독을 모두 분리한 완전 요인 실험은 아닙니다.
- 모델·프롬프트·문제·앱 빌드는 본 측정 중 바꾸지 않습니다. 공개 평가 문제의 결과를 보고 해당 문제만 맞히도록 수정한 후 같은 점수를 새 검증 성능으로 보고하지 않습니다. 이는 [OpenAI의 평가 지침](https://developers.openai.com/api/docs/guides/evaluation-best-practices)의 명확한 판정 기준과 기록 원칙에 맞춘 작은 실험입니다.
