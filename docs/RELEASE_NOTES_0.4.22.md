# 0.4.22 — 구독 대화 연결·중단 사유 수정

- Discord에서 발생한 `구독 대화 식별자가 일치하지 않습니다`를 대화 생성 응답보다 상태 알림이 먼저 오는 순서로 재현하고 수정했습니다. 초기 상태 알림은 제한된 범위에서 보류하고, 요청에 대응하는 생성/재개 응답으로 대화 ID를 확정한 뒤 대조합니다. 알림의 ID를 그대로 신뢰하거나 검증을 제거하지 않습니다.
- 실행 시작 응답 전 도착한 텍스트·완료 이벤트를 보류하고 전체 대기 목록의 실행 ID를 검증한 뒤 처리합니다. 이전에 완료된 실행의 늦은 알림은 다음 작업의 완료·중지로 처리하지 않습니다. 정상적인 격리 도구 요청도 실행 ID가 확정된 뒤 기존 도구 권한 검사를 거칩니다.
- 다른 대화/실행 ID, 초기화 전 도구 호출, 허용되지 않은 도구와 과도한 대기 이벤트는 계속 차단합니다. 취소된 작업은 자동 재실행하지 않으며 기존 사용자별 권한·모델 상한을 유지합니다.
- 중단 사유를 사용자 중지, 에이전트 종료, 기기 권한 해제, Discord 연결 중단, Discord 역할·권한 확인 실패, 내부 작업 연결 오류로 구분합니다. 후속 정리 과정에서 최초 사유를 덮어쓰지 않습니다. 과거 일반 중지 기록만으로 당시의 상세 원인을 복원할 수는 없습니다.
- 동일한 알림 순서 문제를 PC/모바일이 사용하는 네이티브 세션에도 수정했습니다. 실질적인 수정은 PC 호스트에 있으므로 기존 모바일 APK와 호환됩니다. 새 APK는 0.4.22 / versionCode 27로 패키징하며 모바일 UI 변경은 없습니다.
- 재연결 시 이전 CLI의 종료를 확인한 뒤 같은 로컬 세션 저장소를 다시 엽니다. 종료와 재시작이 겹쳐 DB 초기화가 실패하던 경우를 보완했으며, 이미 실행 중인 티켓끼리는 계속 병렬로 처리합니다. 종료 대기에도 제한 시간과 취소를 적용합니다.

검증: 합성 알림 순서 재현, 대화/실행 분리·이전 완료 알림·대기 한도·취소·중단 사유 테스트. 설치된 실제 Codex와 로컬 가상 공급자를 사용해 알림 순서를 바꾼 상태에서도 격리 텍스트·도구 실행·네이티브 세션 재사용/재시작을 확인합니다. 이 테스트는 사용자 계정의 추론 요청이나 실제 Discord 채널에 메시지를 보내지 않습니다.
