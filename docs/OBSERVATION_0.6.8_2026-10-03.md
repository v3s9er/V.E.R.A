# 0.6.8 일반 실행·세션·UI 검증

## 확인한 결함과 수정

1. 네이티브 및 격리 브로커 실행이 여러 공개 메시지를 스트리밍하고도 마지막 본문만 최종 결과로 반환했다. 이전 출력이 저장 기록에서 빠지고 후속 대화의 정본이 달라질 수 있었다. 모든 공개 답변을 일치시켜 저장하도록 수정했고, 복수 메시지 이후 같은 세션의 다음 요청까지 검사했다.
2. 네이티브 재구성 입력의 `JSON.stringify(history).slice(-48_000)`는 JSON과 역할/도구 경계를 깨뜨릴 수 있었다. 최근 사용자 요청 단위의 유효한 레코드를 전달하고, 큰 최신 묶음의 발췌 및 생략을 표시한다. 큰 도구 payload를 잘라 정상 도구 호출처럼 전달하지 않는다. 원본 저장 기록은 유지한다.
3. 완료되지 않은 델타가 남아 있어도 완료 이벤트만으로 성공 처리할 수 있었다. 미완성·순서 역전·변조된 중복 완료·완료 후 델타·전체 출력 한도에 대한 거부 회귀를 추가했다. 실패한 부분 답변의 세션을 정상 완료 체크포인트로 저장하지 않는다.
4. 390×780, 390×430, 320×480에서 Daybreak가 입력창 밖으로 밀리는 것을 강화된 경계 검사로 재현했다. 기본 CSS와 나중에 로드되는 실행 패널 CSS의 nowrap 규칙을 함께 수정했다. 작은 화면의 Daybreak는 접근성 이름과 pressed 상태를 갖는 아이콘 버튼이다.
5. UI 자동검사가 외부에서 미리 켜둔 고정 포트 서버에 의존했다. 임시 서버를 직접 열고 닫으며, 외부/실제 RPC 요청과 HMR을 차단한다. 모델 설정 저장 후 상태 확인도 즉시 단발 검사 대신 실제 UI 상태 도달을 기다린다.

프로토콜 처리 기준은 [공식 Codex App Server 문서](https://learn.chatgpt.com/docs/app-server)의 스레드·턴 상관관계, 스트림 완료와 interrupt 수명주기다. 실행 권한이나 도구 허용 범위를 낮춰서 검사한 것이 아니다.

## 실제 설치 앱 검사

기존 로컬 관리자 인증으로 설치 앱의 `chat.start`를 사용했다. 앱을 우회한 직접 CLI 호출을 실제 앱 평가로 세지 않는다. 합성 시험은 아래에 별도로 구분한다.

- 동일 모델 `gpt-6-astra`, 추론 high, Daybreak off, full 권한, quality 정책.
- 별도 프로젝트의 합성 `input.json`만 읽는다. 기존 PC 파일, 외부 서비스, 사용자 대화는 평가 입력으로 사용하지 않는다.
- 새 대화에서 파일 읽기/합계 → 파일을 다시 읽지 않는 후속 기억 → 20초 대기 명령 중 취소 → 앞선 값 기억을 확인하는 재개.
- 변경 전 2개 대화 8건, 변경 후 2개 대화 8건: 정상 응답 12건의 합계/참조값·스트림/결과 일치, 취소 4건 모두 통과. 후속 기억/재개에는 도구 호출이 없었다. 실행 종료 후 활성 작업 0개, 4개 대화의 저장 모델·추론·권한·Daybreak 설정 유지 확인.
- 검사 대화 4개는 정본 입력·응답을 확인한 뒤 보관함으로 이동했다. 검사 프로젝트 연결만 해제하고 파일·원본 보고서는 삭제하지 않았다.

### 시간 측정

각 셀은 **측정값 2개를 모두 나열**한 초 단위 값이다. 적은 표본의 순차 검사이며 무작위 교차 시험이 아니다. 네트워크/서비스 상태를 통제하지 않았으므로 이 차이만으로 속도 개선을 입증하지 않는다.

| 요청 | 0.6.7 첫 출력 | 0.6.8 첫 출력 | 0.6.7 완료 | 0.6.8 완료 |
|---|---|---|---|---|
| 파일 읽기·합계 | 11.325 / 15.490 | 15.460 / 9.497 | 12.349 / 16.395 | 16.671 / 10.482 |
| 후속 기억 | 3.357 / 4.027 | 2.104 / 2.453 | 4.239 / 4.793 | 2.592 / 4.137 |
| 취소 후 재개 | 6.443 / 6.066 | 4.926 / 5.046 | 7.630 / 7.328 | 6.104 / 6.561 |

취소 요청에서 `chat.start`가 종료될 때까지: 변경 전 0.309 / 0.434초, 변경 후 0.266 / 0.367초. 요청 자체는 실제 명령 실행 시작 때 취소했으며, 전체 요청 시간과 취소 지연을 혼동하지 않는다.

새 계측에서 신규 작업의 CLI 접수는 앱 시작 기준 0.566 / 0.707초, 기존 세션 후속 요청은 0.028–0.041초였다. 따라서 남은 수 초 전체를 Mr.Robot의 준비 시간이라고 볼 수 없다. 접수 이후에는 CLI·네트워크·모델·도구 실행이 포함되며 공급자의 순수 추론 시간을 따로 측정하지 않았다.

취소 직후 새 요청은 이전 프로세스 핸들 종료 확인에 약 1.00–1.05초를 썼다. 잠금 충돌과 불확실한 부분 작업 재실행을 막는 경계이므로 없애지 않았다. 새로운 모델 호출을 하는 백그라운드 예열, 유료 우선 처리, 모델 자동 하향은 사용하지 않았다.

## 회귀 검사

- 전체 `npm test` 통과: 에이전트/Discord 권한·격리·파일·원격 연결, 예산, 저장/복구, 스케줄, UI 계약, 세션, 조율, 튜닝, 계측, 외부 평가 어댑터, 적응형 실행/온톨로지/이미지 증거, 네이티브 창 복구 등 포함.
- `npm run typecheck`와 반응형 UI 계약 통과.
- 추가 `test:agent-runtime`, `test:remote-security`, `test:model-catalog`, `test:desktop-native` 통과.
- 실제 설치 Codex를 합성 로컬 HTTP 공급자에 연결한 `test:codex-installed` 통과: 텍스트·격리·브로커·네이티브 재사용/재개. 실제 계정 모델 정확도 평가가 아니다.
- 네이티브 스케줄/스트리밍/중단 회귀 28개와 별도 네이티브 풀 시험 통과. 환경이 다른 프로세스/체크포인트를 공유하지 않는 시험 포함.
- `test:ui-live` 최종 통과: 입력창 7개 크기(320×480 포함), 모델 선택 3개 크기, 캘린더 5개 크기 × 일정/플러그인 2개 화면. 실제 앱 구성요소 + 합성 데이터 + 전용 headless Edge 프로필. Android 기기/실제 키보드 시험은 아니다.
- 최종 staged Electron 창 렌더링, 입력창 가시성, renderer crash 후 자동 복구 및 agent PID 유지 통과.
- 공개 소스/도달 가능한 Git 이력의 알려진 토큰·개인 상태·서명 자료 검사와 `git diff --check`를 수행한다. 이 검사가 가능한 모든 비밀의 부재나 전체 앱 무결함을 증명하지는 않는다.

실패한 검사도 숨기지 않는다. 처음 UI 시험은 고정 포트 서버 부재로 시작하지 못했다. 새 경계 검사는 3개 화면에서 실제 Daybreak 넘침을 발견했고, CSS 한 군데만 고친 중간판은 320px에서 여전히 실패했다. 최종 두 CSS 규칙 수정 후 7개 크기 통과. 빌드 중 HMR/비동기 상태 도달 전에 검사한 모델 선택 실패도 보존하고, HMR 없는 서버와 상태 대기 후 재검사했다. 변경 후 첫 실측 준비는 이미 등록된 검사 폴더를 다시 만들려다 중단되었으며, 모델 호출 없이 기존 검사 프로젝트를 검증해 재사용한 8건을 본 측정으로 기록했다.
