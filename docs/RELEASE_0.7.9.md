# V.E.R.A 0.7.9

## 네이티브 에이전트 중심 실행

기본 Codex 작업은 구독 에이전트가 직접 지휘합니다. 허용된 로컬 무제한 집계 실행에서는 구독 CLI의 보조 작업을 사용하고, V.E.R.A 보조 작업을 동시에 붙이지 않습니다. 단순 응답은 기존의 같은 모델·도구 없는 빠른 경로를 유지합니다. 사용자가 명시적으로 고른 다중 모델 프리셋은 유지합니다.

보조 작업은 부모와의 실제 이벤트 관계를 확인하고, 자식의 답변·도구·사용량이 다른 대화나 부모 결과에 섞이지 않게 합니다. 최신 CLI의 `subAgentActivity`도 추적합니다. 중단·실패와 정상 완료 모두 소유 프로세스 종료를 확인하며, 미완료 보조 작업을 완료로 표시하지 않습니다. 보조 작업 활성화 경로는 실제 자식 관측 여부와 무관하게 종료 확인 후 다음 요청에서 주 대화 세션을 복원합니다. 이 경로의 전체 사용량은 확인 불가로 표시하고 부모 토큰만으로 총량을 단정하지 않습니다.

CLI의 자식 모델·추론 설정은 기본값이지 강제 허용 목록은 아닙니다. 관측된 변경은 중단하지만 공급자 측에서 이미 시작했을 가능성은 있습니다. 따라서 엄격한 모델 제한이 필요한 Discord에는 이 경로를 적용하지 않습니다. Discord의 기존 관리자 지정 모델·추론, 사용자별 권한과 티켓은 그대로입니다.

## 작업 온톨로지와 근거 검사

기존 프로젝트 지식 온톨로지에 작업 단위의 의존관계·완료 보고·파일 검사 근거를 추가했습니다. 별도 계획 모델 없이 주 모델이 필요할 때 사용합니다.

- 최대 12개 작업의 선행 관계를 검증하며 순환·누락된 참조를 거절합니다.
- 모델의 ‘완료’ 보고만으로 검증 완료가 되지 않습니다. 명시한 파일 존재·내용·SHA-256 조건과 선행 작업 검사를 통과해야 합니다.
- 수정 가능성이 있는 도구 이후에는 기존 근거를 무효화합니다. 수정→검사를 반복할 수 있고, 최종 종료 전에 요청했던 검사를 다시 확인합니다.
- PC·웹·모바일 소스 화면에 완료 보고와 파일 조건 확인을 따로 표시합니다. 원시 JSON·파일 내용은 진행 화면에 노출하지 않습니다.
- 작업 장부는 현재 실행에만 유지됩니다. 예전 작업의 검증을 현재 사실로 재사용하거나, 중단된 부작용을 자동 재실행하지 않습니다.

이는 지정한 파일 조건 검사이며, 전체 답변 정확도·보안·테스트 통과를 자동 보장하지 않습니다. 설계와 범위는 [네이티브 실행·작업 온톨로지](native-first-work-ontology.md)에 정리했습니다.

## 검증

- 전체 `npm test`와 최종 변경 영향 범위인 작업 온톨로지·조율·튜닝·AI 루프·타입 검사를 통과했습니다.
- 실제 앱 경로: 개발 검사 6/6, 최종 빌드 재검사 3/3 통과. 정확한 파일 생성, 실패한 파일 조건 수정, 같은 모델의 도구 없는 인사를 확인했습니다.
- 실제 Codex 0.159.3 / `gpt-6-sol/high`: 보조 작업 1개 생성·대기·결과 및 종료 확인 통과.
- 이것은 기능 검증입니다. 단독 Codex/Claude보다 정확하거나 빠르다는 비교 결과는 아닙니다. 자식 전체 토큰 집계도 아직 확인할 수 없습니다.

## 배포 및 데이터

Windows PC 에이전트/웹 업데이트입니다. Android 화면 소스도 갱신하지만 이번 릴리스에 새 APK를 배포하지 않습니다. 공개 Android APK는 0.7.2(versionCode 48)이며 이후 APK 배포에는 versionCode 증가가 필요합니다. 기존 설치 ID·프로필·페어링·MIT 라이선스를 유지합니다. 설치 파일은 미서명입니다.

실제 사용자 정보, 자격증명, 대화, 개인 백업과 평가 원문은 공개 소스 및 배포에 넣지 않습니다. ARTEX 코드를 복사하지 않고 작업 상태와 근거 분리라는 설계 아이디어만 참고했습니다.
