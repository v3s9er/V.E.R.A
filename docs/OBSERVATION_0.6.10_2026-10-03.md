# 0.6.10 도구 실행·검색 검사 — 2026-10-03

## 재현 가능한 국소 비교

`npm run benchmark:tool-scheduling`은 유료 모델·외부 MCP 서버 없이 동일한 합성 입력을 기존/개선 방식에 넣습니다. 실행 순서를 번갈아 6회씩 측정합니다.

- 읽기 지연 fixture: `[120, 15, 15, 90, 15, 15]` ms. 기존 고정 3개 묶음의 중앙값 216.15 ms, 빈 레인 즉시 보충 방식 123.5 ms. 약 43% 감소는 **이 합성 스케줄러 구간만**의 관측입니다. 양쪽 결과 순서는 동일했습니다.
- 240개 도구 중 마지막 도구를 찾는 fixture: 기존 12개씩 목록 조회+schema는 21회/20,143자, 검색+schema는 2회/566자였습니다. 양쪽 schema는 같았습니다. 도구가 뒤에 있는 특정 사례로 일반화할 수 없으며 문자 수는 토큰 사용량이 아닙니다.
- 설치 빌드 후 동일 스크립트 재검사에서도 읽기 중앙값 215.25 → 123.15 ms, 검색 21 → 2회 및 20,143 → 566자로 확인했습니다. 이 재검사도 합성 입력이며 실모델 측정이 아닙니다.
- 실제 앱의 처음 출력 시간·완료 시간·정답률을 비교한 실모델 A/B는 이번에 수행하지 않았습니다. 네이티브 CLI 자체의 파일 스케줄러는 이 변경 대상이 아닙니다. MCP 검색은 기존 네이티브 호스트 도구 연결에도 노출됩니다.

## 회귀 및 경계

- 집중 검사 35개: 읽기 레인 보충·원래 순서·동시 3개 상한·쓰기 대기, 실패/취소 후 새 작업 중지와 시작한 읽기 정리, MCP 검색/페이지/schema/목록 무효화, 공급자 스트림.
- Claude API의 텍스트/추론 후 도구 호출과 교차 JSON 조각을 검사합니다. 잘린/중복/미완료/종료 누락/인덱스 누락/손상 이벤트 등 12개 불완전 스트림에서 실행 가능한 도구 이벤트가 나오지 않아야 합니다.
- 첫 전체 회귀 실행은 새 검색 결과 union 때문에 벤치마크 스크립트 두 곳의 TypeScript 검사에서 실패했습니다. schema 결과를 명시적으로 구분하도록 수정했습니다. 실패를 성공 기록에 포함하지 않습니다.

## 완료한 검사

- `npm test` 전체 회귀와 TypeScript 검사 통과. 마지막 스트림 경계 추가 후 집중 35개를 다시 통과했으며 새 설치 빌드의 에이전트 컴파일도 통과했습니다.
- 실제 Electron에서 임시 앱 데이터·별도 포트로 새 빌드를 열어 입력창 표시, 렌더러 강제 충돌 후 복구, 에이전트 PID 유지 검사 통과. 사용자 대화·Discord나 모델은 이 검사에서 실행하지 않았습니다.
- 공개 소스/도달 가능한 이력의 경로·토큰 형식 검사 통과. 추가로 로컬에 알려진 자격증명 11개(복호화 4회)를 값 출력 없이 소스 index·도달 가능한 이력·데스크톱 stage 957개 검사 표면과 대조해 일치가 없었습니다. 미지의 비밀·짧은 PIN의 부재를 보장하지 않으며 APK는 검사 범위가 아닙니다.
- 외부 소스 압축 파일·비공개 코드·사용자 설정·인증 자료를 Git에 추가하지 않았습니다. 기존 미추적 설치 파일도 변경하지 않았습니다.

측정 원시 로그와 로컬 연결 정보는 Git에서 제외된 `release/validation`에만 보존합니다.
