# 0.6.6 검증 기록

## 재현한 문제와 수정 범위

0.6.5의 기존 단일 실행 기록에서 `evidence_image` 결과를 첫 `data:image` 뒤
전체 문자열로 잘라 전달했다. 그 뒤에 확대본 설명과 두 번째 이미지가 있어
유효한 이미지 URL이 아니었다. 여러 재시도 뒤에도 원본만 표시하고 확대본은
누락했다. 도구 사용법이 한 장 기준으로 남아 있던 계약 오류다.

0.6.6의 첫 수정(r12)은 모든 이미지 분리 표시를 실제 도구 호출에서 확인했지만,
이미지의 대문자를 소문자로 바꾼 계산이 남았다. 최종 수정은 불일치 OCR 후보를
기본 전사문에서 불확실 영역으로 격리한다. 원본 픽셀과 좌표는 보존하며,
명시 요청 시 원시 후보를 둘 다 반환한다. 같은 엔진의 재검사를 독립 투표로
취급하거나, 정답에 맞춰 문자를 자동 수정하지 않는다.

원본 해시, 워크스페이스 제한, 읽기 전용 도구, 이미지 크기/시간/동시성 제한,
OCR의 `verified:false`, 계산 검산의 `originalExecuted:false`는 유지한다.

## 평가 방법과 첫 수정의 실패

실제 설치된 앱의 인증된 `chat.start`를 사용한다. CLI를 직접 호출해 앱 경로를
우회하지 않는다. 정확한 `gpt-6-sol`, medium, Daybreak 끔, workspace 권한,
동일 입력으로 단일/온톨로지/회의형/결합형을 새 대화에서 비교한다.
온톨로지에는 문제의 주어진 사실만 넣고, 회의형은 독립 독자 2명과 최종
판정자다. 모델 변경/암묵적 대체를 허용하지 않는다.

자가 제작 코드 이미지 2장당 언어·거부 입력·허용 입력 결과 총 6개 필드다.
6개의 독립 대회 문제가 아니며 공식 대회 점수가 아니다. CPython 기준값은
모델 실행 전에 고정하고 모델의 작업공간 밖에 둔다. 원본 이미지와 정답,
계정/대화 식별자 및 도구 기록은 공개 저장소에 포함하지 않는다.

| v4 대소문자 사례 | 단일 | 온톨로지 | 회의형 | 결합형 |
| --- | ---: | ---: | ---: | ---: |
| 0.6.5 r11 | 5/6 | 6/6 | 6/6 | 6/6 |
| 0.6.6 첫 수정 r12 | 5/6 | 6/6 | 5/6 | 6/6 |

첫 수정의 완료 시간은 순서대로 28.970/22.288/53.429/51.433초였다.
전달 오류 수정만으로 정확도가 해결됐다고 주장하지 않는다. 이전 실패 기록은
보존하며 새 실행으로 대체하지 않는다.

r15는 완료 51.448/29.691/47.851/53.012초이며, 네 응답의 모델/실행 구성/
저장 답변 일치를 확인했다. 다만 합성된 설정 불변 검사 결과가 false였고 이전
비교 항목의 스냅샷이 없어 차이 원인을 소급 확정할 수 없다. 따라서 이 실행을

실행부터 라우팅·플러그인·메모리 ID·공급자 비교를 별도로 기록한다. 사용자의
설정을 과거 값으로 되돌리지 않았다.

r13은 완료 34.287/36.141/55.935/56.615초다. 네 설정 비교가 모두 true였고,
평가에서 추가한 scoped 메모리를 제거했으며 종료 후 실행 중 작업은 0개였다.

r14는 두 번째 수정 소스를 확정하기 전에 기준 이미지를 생성·고정했고 모델에
한 번도 제시하지 않았던 자료다. 이후 소스의 일반 문자열 격리 처리를 보완했으나
문제·답을 그 코드에 넣지 않았다. 완료 시간은 30.630/30.500/56.721/51.396초,
네 설정 비교 모두 true다. 단일도 정답이며 회의형이 더 느리므로, 회의형을
항상 켜거나 보편적으로 우수하다고 결론내리지 않는다.

r16은 추가 코드 변경 없이 같은 대소문자 사례를 새 대화에서 반복한 결과다.
완료 49.280/32.748/73.690/56.947초, 네 설정 비교 true, 종료 후 실행 0개다.
r15의 검사 불확실성은 지우지 않고, 별도의 재실행으로 구분한다.

## 자동/설치 검증

- 이미지 수정 후 전체 `npm test`, 웹/에이전트/모바일 타입 검사 통과.
  후속 단순 답변 반복 수정 후에는 영향받는 추론/네이티브 회귀 30개,
  튜닝·세션·AI 루프와 전체 타입 검사를 다시 통과했다.
- 이미지 전송 예제 실행, 좌표별 RGBA 보존, 불일치 후보 격리,
  정규식 이스케이프·겹친 후보·반복 공백·명시적 원시 후보 확인 검사 통과.
- 원본 접근 범위, 순수값 검산, 취소·세션·오케스트레이션·온톨로지·원격 연결
  등의 기존 회귀 검사를 유지했다. 계산 검산은 전사 정확성의 증명이 아니다.
- 분리된 실제 Electron 인스턴스에서 창 표시→렌더러 강제 종료→입력창 복구,
  에이전트 프로세스 유지 확인. 첫 테스트의 포트 충돌 실패도 기록에 보존했다.
- 설치된 `app.asar`가 빌드 산출물과 일치함을 대조하고 네이티브 앱을 다시 열었다.
- 이미지 실험 당시 Windows 설치파일 SHA-256(후속 경량화 빌드와 구분):
  `6f99e255c3457b8b2f5d1a8d67219c7fc173b0af0530b1f5c65d41fe29682f54`.
- 새 외부 라이브러리를 추가하지 않았다. 민감정보 패턴 검사는 공개 소스와
  도달 가능한 Git 이력을 대상으로 하며, 모든 비밀정보 부재를 보증하지 않는다.
- 실제 메시지와 프로젝트 소유권이 일치한 평가 대화 22개를 보관 처리하고,
  대화/파일이 없는 평가용 프로젝트 등록 5개만 해제했다. 파일 삭제는 없으며
  이미지·기준값·실험 결과는 비공개 검증 폴더에 보존했다. 종료 후 실행은 0개다.

## 후속 경량 대화 검증 및 최종 설치본

이미지 평가 뒤 같은 앱에서 `gpt-6-astra`, 저장 추론 high, Daybreak 끔, full
권한으로 인사→단순 산술→직전 식과 답 재질문을 검사했다. 재질문은 일반 경로로
돌아가 8.473초 걸렸다. 직전의 도구 없는 단순 답변만 명시적으로 반복하는 요청을
문맥과 함께 경량 처리하도록 보완했다. "다시 작업해" 등 부작용 재실행 요청은
해당하지 않는다. 실제 작업으로 바뀌면 native/high 및 기존 권한을 유지한다.

| 요청 | 경량 재질문 수정 전 완료 / 첫 답변 | 수정 후 완료 / 첫 답변 |
| --- | ---: | ---: |
| 인사 | 6.307 / 6.142초 | 5.881 / 5.711초 |
| 단순 산술 | 2.398 / 2.199초 | 2.390 / 2.216초 |
| 직전 식과 답 재질문 | 8.473 / 7.801초 | 3.346 / 3.210초 |

최종 세 요청 모두 실제 추론 low, 선택 모델 유지, 도구/보조 에이전트 0회,
대화 기억·저장된 high/Daybreak/권한 유지 검사를 통과했다. 별도 분류 모델이나
고정 답변을 넣지 않았다. 단일 순차 표본이며 P95/전반적 속도 개선의 증거는
아니다. 특히 첫 인사는 여전히 약 5.9초로, 공급자/네트워크 시간을 포함한다.

이미지 평가 뒤 변경한 것은 이 문맥 기반 경량 분기 및 테스트이며 이미지
전달/OCR 코드는 동일하다. 이미지 평가 당시 번들은 비공개 검증 자료와 함께
보존했다. 최종 설치·빌드 `app.asar` 일치 SHA-256:
`de232f671ab8a3228481b9892a75397630b20bbe2951e9a9c4af9aec38fb5252`.
최종 Windows 설치파일 SHA-256:
`30a2978f43a5abf5db929b505d3aa6d77f5486618fa2f27f13cee0b5824775d9`.

## 해석의 한계

작은 근접 전이 평가이며 고정 실행 순서·캐시·공급자 부하가 통제되지 않는다.
회의형은 더 많은 계산을 쓰므로 동일 비용 비교가 아니다. 전체 앱 테스트 통과도
모든 현실 작업의 정확성·취약점 부재를 증명하지 않는다. 물리 Android 기기의
키보드/파일 다운로드 및 모든 공급자를 이번 검사로 보증하지 않는다.

프로토콜 계약은 [OpenAI Docs의 App Server 동적 도구 반환](https://learn.chatgpt.com/docs/app-server)을
확인했다. 규격 지원과 모델이 실제로 모든 반환 이미지를 표시했는지는 별도로
검증한다. 원본·관찰·검산을 구분하는 기존 증거 규칙을 유지한다.
