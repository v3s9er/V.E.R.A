# V.E.R.A 0.7.1

## 여러 대화와 프로젝트 목록

- 하나의 연결에서 다른 대화를 시작하면 `chat already running`으로 막히던 연결 단위 실행 상태를 대화별 실행 상태로 분리했습니다. 취소, 추가 지시, 승인과 진행 표시는 해당 대화에만 적용됩니다.
- 서로 다른 프로젝트는 동시에 실행할 수 있습니다. 같은 프로젝트에서 파일을 바꿀 수 있는 작업은 선행 작업 뒤에 대기하며 대기 상태를 표시합니다. 읽기 전용 작업끼리는 병렬 실행할 수 있습니다. 이는 충돌을 줄이는 스케줄링이며 파일 접근 보안 경계는 기존 권한 정책입니다.
- PC·모바일의 새 대화 생성과 전환에서 중복 클릭, 늦은 로딩 결과, 다른 대화의 설정 저장 결과가 현재 화면을 덮는 문제를 방어합니다. 대화별 초안을 보존합니다.
- 작업 목록을 프로젝트별로 접고 펼치며 접힘 상태를 저장합니다. 빈 대화, 진행 중 작업과 대기 작업을 구분합니다.

## 실행 도중 모델·권한 변경

모델, 추론, 권한, 질문 예산과 Daybreak 설정을 실행 중에도 저장할 수 있습니다. 현재 실행의 실제 설정과 **다음 실행에 적용할 설정**을 구분해 표시합니다. 현재 작업에도 새 설정을 적용하려면 **중지하고 적용**을 사용하고 후속 지시를 보내세요.

실행 식별자와 소유자를 확인하고 기존 실행의 종료를 기다립니다. 중단된 요청과 부분 응답은 완료 결과가 아님을 표시해 보관합니다. 이미 실행된 파일 수정이나 외부 전송이 반복되지 않도록 원래 요청을 자동 재실행하지 않습니다. CLI의 실행 중 입력 추가는 모델·샌드박스 교체가 아니므로 실행 권한이 바뀐 것처럼 표시하지 않습니다. 프로젝트 이동은 실행 종료 후 가능합니다.

## 이름과 오래된 화면 진단

실행 파일명을 `V.E.R.A.exe`로 변경합니다. 설치 ID, 프로필, 페어링과 암호화 식별자는 유지합니다. 이전 프로그램이 실행 중이면 설치를 중단하며 임의로 종료하지 않습니다. 기존 작업 표시줄 고정 바로가기는 새 실행 파일에 다시 고정해야 할 수 있습니다. [마이그레이션 안내](DESKTOP_IDENTITY_MIGRATION.md)를 참고하세요.

클라이언트 HTML은 저장된 캐시를 재사용하지 않으며 없는 자바스크립트 파일 요청에 HTML을 반환하지 않습니다. 프로필 메뉴의 클라이언트 버전·소스 지문으로 화면 자산을 구분합니다. 이 지문은 실행 파일 전체의 해시가 아닙니다.

## 실제 컴퓨터·브라우저 도구

기존 Windows 컴퓨터 도구는 창 조회 → 관찰 → 단일 동작과 후속 확인 흐름을 유지합니다. 보조 프로세스가 종료되기를 기다리는 동안 취소·시간 제한이 적용되지 않던 문제를 수정했습니다. 종료 확인 전 새 보조 프로세스를 만드는 안전 장벽은 유지합니다.

새 구조화된 브라우저 도구는 설치된 Edge/Chrome의 **별도 임시 세션**에서 페이지를 열고, 제한된 DOM을 읽고, 관찰한 요소를 클릭하거나 일반 입력 필드에 입력합니다. Codex 네이티브 경로와 도구 호출을 지원하는 API 모델의 전체 허용 실행에 연결됩니다. 기존 브라우저의 쿠키·로그인·프로필을 가져오지 않으며 일반 JavaScript 실행, 임의 실행 파일, 외부 CDP 연결은 노출하지 않습니다. 브라우저 자동화 라이브러리는 실제 사용 시에만 로드합니다.

이 버전은 메인 프레임 DOM 기반 기능입니다. 화면 이미지 판독, 모든 사이트·iframe 지원, 로그인 자동화나 기존 인증 세션 승계를 주장하지 않습니다. 관찰은 만료되는 단일 사용 토큰이며 불확실한 동작을 자동 반복하지 않습니다. 보호된 필드·다운로드·팝업·비웹 URL은 제한됩니다. 전체 허용이라도 OS·회사 정책을 우회하지 않습니다.

## 관리형 샌드박스 플러그인

`managed-sandbox` 플러그인에 상태 확인, 준비, 실행, 중지와 제거 도구를 추가했습니다. 같은 대화의 작업 공간을 재사용하며 Docker Linux 엔진과 WSL 기반 Docker 엔진을 지원합니다. **WSL 자체를 보안 샌드박스로 간주하거나 실패 시 호스트 실행으로 전환하지 않습니다.**

호스트 폴더나 Docker 소켓을 마운트하지 않고 네트워크 없음, 읽기 전용 루트, 비루트 실행, 권한 제거, CPU·메모리·프로세스·임시 공간·출력·시간 제한을 적용합니다. 준비된 로컬 이미지와 엔진만 사용하며 설치·다운로드·엔진 시작은 자동으로 하지 않습니다. 임시 작업 공간이므로 중지·제거·시간 제한 후에는 결과가 없어질 수 있습니다. [샌드박스 안내](MANAGED_SANDBOX.md)를 참고하세요.

## 검증 범위

동시 실행·대화별 취소·프로젝트 대기·실행 설정 적용·권한 상한과 소유권 회귀 검사, PC React 화면의 여러 폭 검사, 모바일 타입·UI 계약 검사, 브라우저의 로컬 합성 페이지 동작 검사, 샌드박스의 가짜 Docker 응답 기반 격리·실패 처리 검사를 구분합니다. Docker 엔진을 사용할 수 없는 환경의 테스트를 실제 컨테이너 실행 성공으로 계산하지 않습니다. Android 실제 기기 조작과 모든 Windows 환경의 동작을 보장하는 결과도 아닙니다.

빌드 및 설치 완료 여부는 GitHub Releases의 실제 자산과 설치본 버전을 확인하세요. MIT와 의존성별 저작권 고지는 유지합니다.
