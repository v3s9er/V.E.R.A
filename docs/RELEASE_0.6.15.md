# Mr.Robot 0.6.15 실행 효율과 복구 신뢰성

협업 비용, 긴 대화의 기억, 완료 판단, 지연 측정, 연결 복구의 다섯 영역을 개선했습니다. 입력 안에서 끝나는 계산은 PC 도구용 문맥을 생략하고, 확인되지 않은 작업을 성공이나 유휴 상태로 오인하지 않도록 수정했습니다. 모델의 일반적인 정답률 향상이나 모든 환경에서의 속도 향상을 주장하지 않습니다. 기존 공급자, 모델, 권한, 사용자의 협업 프리셋은 자동으로 바꾸지 않습니다.

## 협업 판단과 불필요한 작업 감소

적응형 주 모델은 사용자의 완료 조건에 필요한 근거를 먼저 확보하고, 독립된 정확한 파일 경로는 묶어서 읽도록 안내합니다. 구체적인 미해결 사항 없이 폴더를 뒤지거나 동일 자료를 다시 읽거나 검토 단계를 추가하지 않도록 했습니다. 새로운 근거가 결과를 바꿀 수 있는 독립 작업만 위임합니다. 보조 모델의 출력은 신뢰할 수 없는 자료이며, 다수결이나 같은 의견의 반복은 검증으로 취급하지 않습니다.

동일한 `gpt-6-sol`, 추론 `high`, 읽기 전용 조건에서 실제 Electron 앱의 인증된 요청 경로로 검사했습니다. 6개 JSON 파일에 있는 48개 합성 검증 기록에서 상태 문구가 아닌 종료 코드, 실패 개수, 해시, 커밋 일치를 대조하는 과제입니다. 파일 안의 잘못된 지시는 따르지 않아야 합니다. 정답은 별도로 고정한 실패 ID 목록으로 채점했습니다.

| 실행 구성 | 정답 | 종료 시간 중앙값 | 토큰 중앙값 |
| --- | --- | --- | --- |
| 지침 개선 전 단일 실행 | 3/3 | 12.00초 | 31,924 |
| 지침 개선 전 적응형 | 3/3 | 33.30초 | 71,538 |
| 지침 개선 후 단일 실행 | 3/3 | 14.60초 | 32,003 |
| 지침 개선 후 적응형 | 3/3 | 13.37초 | 30,777 |

단일 대조군에서는 Mr.Robot의 보조 실행을 끈 프로필을 사용했습니다. 적응형은 같은 모델의 보조 작업을 선택할 수 있었지만 위 비교에서는 모두 직접 처리했습니다. 따라서 이 결과는 **적응형 주 모델의 불필요한 실행 비용 감소**를 관찰한 것이지 다중 에이전트의 정답률 우위를 입증한 것이 아닙니다. 개선 전 적응형의 호스트 도구 호출은 13·18·19회, 개선 후는 모두 6회였습니다. 비교와 별도로 두 보조 모델을 명시적으로 호출하는 기능 검사도 수행했습니다.

별도의 두 보조 모델 기능 검사는 개선 전 43.34초·122,862토큰, 개선 후 49.35초·210,481토큰이었고 두 번 모두 정답과 두 보조 작업의 완료를 확인했습니다. 각 1회인 기능 검사이므로 성능 비교의 표본에는 포함하지 않습니다. 분업을 강제하면 이 작은 과제에서는 오히려 비용이 커졌다는 한계도 남아 있습니다.

동일한 합성 과제를 각 구성에서 세 번 반복한 개발 검사입니다. 단일 실행에도 시간·토큰 변동이 있었고, 공개 대회 점수나 미관측 과제의 일반 성능으로 해석할 수 없습니다. 불필요한 협업을 기본적으로 늘리지 않습니다.

## 긴 대화와 실행 복구

- 문맥 압축 시 이전 요약을 단순히 뒤에서 잘라 붙이지 않고, 초기의 주요 사용자 제약과 최근 수정 사항을 함께 보존합니다. 미해결 사항과 모델의 주장을 구분합니다.
- 모델이 말한 검증 완료는 검증된 사실로 저장하지 않습니다. 발췌는 역할을 표시한 인용 데이터이며 새로운 지시나 완전한 작업 상태가 아닙니다.
- 발췌는 최대 64KiB와 항목별 한도 안에서 보관합니다. 모든 조건을 무한히 기억한다는 뜻은 아니며, 전체 원문은 기존 대화 보관소에 유지합니다.
- 응답이 종료됐어도 진행 중이던 도구의 완료 확인이 없으면 복구 기록은 불확실 상태를 유지합니다. 전송·삭제 같은 부작용을 자동으로 다시 실행하지 않습니다.

## 관찰과 완료 표시

- PC와 모바일에서 최종 응답 종료는 `응답 완료`로 표시합니다. 실제 작업의 성공이나 정답 보증과 구분합니다.
- 완료 확인을 받지 못한 도구를 자동으로 성공 표시하지 않습니다. 완료되지 않은 보조 작업도 성공으로 승격하지 않습니다.
- 콜론이 들어간 서로 다른 도구 호출 ID가 접두어 비교 때문에 잘못 연결될 수 있던 문제를 수정했습니다.
- 실행 목록 조회가 실패하면 작업이 없는 것으로 처리하지 않습니다. 연결 상태를 확인한 뒤 `상태 다시 확인`을 누를 수 있고, 이 동작은 새 요청을 전송하지 않습니다. 같은 대화의 입력 초안도 유지합니다.

## 응답 지연과 측정

단일 실행과 적응형 실행의 사전 준비가 같은 제한적인 텍스트 판별을 사용합니다. 명확한 인사·입력 안의 텍스트 변환·숫자 계산은 불필요한 플러그인 열거와 프로젝트 지식 조회를 생략합니다. 숫자 계산 경로는 숫자와 제한된 구분자로 이루어진 본문만 허용하며, 파일·웹·최신 정보·저장 요청은 기존 도구 경로를 유지합니다. 선택한 모델과 계산 요청의 높은 추론 설정은 유지합니다.

다음은 협업 지침을 추가 조정하기 전, 텍스트 경로 변경을 검증한 실제 앱 측정입니다. 각 행은 같은 요청 세 번의 중앙값입니다. 토큰은 공급자가 보고한 입력·출력 합이며 과금액과 다릅니다.

| 검사 | 모드 | 변경 전후 종료 시간 | 변경 전후 토큰 |
| --- | --- | --- | --- |
| 입력에서 값 추출 | 단일 | 3.97 → 3.44초 | 3,427 → 3,436 |
| 입력에서 값 추출 | 적응형 | 3.04 → 4.18초 | 3,367 → 3,352 |
| 입력 숫자 조건부 합산 | 단일 | 5.38 → 3.43초 | 10,894 → 3,464 |
| 입력 숫자 조건부 합산 | 적응형 | 5.32 → 3.88초 | 10,983 → 3,392 |
| 네 파일 합산 | 단일 | 9.92 → 10.96초 | 25,262 → 25,262 |
| 네 파일 합산 | 적응형 | 10.07 → 10.51초 | 25,442 → 25,454 |
| 검증 기록의 오류 판정 | 단일 | 10.58 → 8.70초 | 24,970 → 24,950 |
| 검증 기록의 오류 판정 | 적응형 | 7.88 → 10.58초 | 25,146 → 37,869 |

변경 전후 각각 24/24회 정답이었으며, 이 검사에서는 보조 에이전트를 호출하지 않았습니다. 중간 구현 검사 24회도 모두 정답이었고 별도 기록을 유지했습니다. 느려진 항목도 포함했으며 전체적인 속도 향상을 주장하지 않습니다. 숫자 합산의 첫 공급자 제출까지 걸린 중앙값은 단일 1,332→133ms, 적응형 1,306→135ms였습니다. 이는 요청 시작부터 첫 제출까지의 관측 시간이지 공급자의 순수 추론 시간은 아닙니다.

성능 설정 화면에는 실패를 포함한 종료 시간의 중앙값·P95, 실패 대기 시간, 첫 제출까지의 시간과 첫 응답 미측정 개수를 추가했습니다. 모델·추론·전송 방식별로 나누어 볼 수 있습니다. 정상 종료는 정답률과 구분하고, 사용자 취소는 실패 포함 지연 통계에서 제외합니다. 측정하지 못한 값은 0으로 계산하지 않습니다.

## 검증 범위와 남은 확인

실제 Electron 앱에서 임시 프로젝트와 기존 공식 CLI 연결을 사용해 다음을 확인했습니다. 개인 대화와 실제 Discord 채널에는 테스트 메시지를 게시하지 않았습니다.

- 요청 수락 후 WebSocket을 끊고 재연결해도 원래 요청이 한 번만 보관되고 응답이 복구됨.
- 두 대화의 동시 실행 중 한쪽 취소가 다른 쪽 응답을 중단하지 않음.
- 앱 프로세스 재시작 후 기존 대화의 값을 기억함.
- 서로 다른 두 대화에서 10회씩 총 20번 후속 질문을 해도 값이 섞이지 않으며 마지막에 실행 중 작업이 남지 않음.
- 실제 Electron 렌더러 종료 후 화면과 입력창이 복구되고 에이전트 프로세스는 유지됨.

자동 검사는 반복 압축 70회, 원문 재로딩·중복 저장 방지·손상 복구, 도구 상태, 실패 지연 통계, Discord 사용자별 세션·병렬 취소·첨부·권한 격리를 포함합니다. 화면 검사는 7개 크기, 재연결 실패 시 초안 유지와 중복 요청 방지, 모델 선택, 캘린더를 포함합니다. 원격 파일 검사는 암호화·변조·재전송·기기 해제·다운그레이드 거부를 확인합니다.

주요 재검사 명령은 `npm run typecheck`, `npm test`, `npm run test:discord`, `npm run test:agent-runtime`, `npm run test:desktop-native`, `npm run test:ui-live`, `npm run test:remote-security`, `npm run test:desktop-recovery-live`입니다. 마지막 명령은 먼저 데스크톱 스테이징 빌드가 필요합니다.

Android 실기기가 연결되지 않아 실제 키보드·LTE 전환·앱 백그라운드 복귀는 확인하지 못했습니다. Discord 검사는 연결 경계의 자동 통합 검사이며 실제 사용자들의 서버에서 장시간 부하를 건 결과가 아닙니다. 짧은 반복 검사는 수일간의 안정성을 보증하지 않습니다.

설치된 앱의 인증된 요청 경로에서 Sol 높은 추론으로 숫자 합산 4.13초, 같은 대화 기억 1.89초, 임시 파일 읽기 6.53초를 확인했습니다. 세 요청 모두 예상 답과 일치했고, 검사 중 공급자·라우팅·메모리 설정은 바뀌지 않았습니다. 각각 1회인 설치 확인이며 성능 순위 측정이 아닙니다. 테스트 대화는 보관하고 임시 프로젝트 등록을 정리했습니다. 설치 파일은 개발용 미서명 빌드입니다.

이 문서는 구현 변경과 실측·미검증 범위를 분리해 작성했습니다. 요청 수신 확인과 최종 완료를 구분하는 수명주기는 [공식 Codex App Server 문서](https://learn.chatgpt.com/docs/app-server)를 참고했습니다. Git 소스 푸시, 설치된 PC 업데이트, GitHub Release 설치 파일 게시, APK 배포는 각각 별도 확인 대상입니다.
