# 0.6.2 — 네이티브 실행 호환성 수정

0.6.1 설치본을 실제 `chat.start` 경로로 비교하던 중, 네이티브 단일 모델
요청이 추론 전에 거부되는 회귀를 발견했다. 부분 실행은 중단했으며 이를
모델의 오답률이나 오케스트레이션의 성능 우위로 해석하지 않는다.

## 원인과 수정

- `turn/start`에 `cyberAccessProgram: "standard"`를 보내면서, 네이티브
  연결의 `experimentalApi` 기능 협상을 동적 도구가 있을 때만 수행했다.
  Daybreak를 꺼도 이 필드가 전달되므로 일반 네이티브 요청까지 거부됐다.
- 항상 필요한 프로토콜 기능을 협상한다. 샌드박스·접근 권한·도구 승인
  검사는 변경하지 않는다. 실행 요청 실패를 자동 재전송하지도 않는다.
- 기능 협상 오류를 로그인 오류와 구분하되 원격 오류 원문·경로·자격증명은
  사용자에게 노출하지 않는다.
- `mcp.result`는 이제 `mcp.discover`/`mcp.call`과 같은 요청 조건에서만
  제공한다. 무관한 수학 질문에 결과 페이징 도구가 붙어 회의 모드의
  도구 실행 모델 선택에 영향을 주던 문제를 줄인다. 이미 선택된 MCP
  실행 안에서는 결과를 재실행하지 않고 다음 페이지를 읽을 수 있다.
- 실제 비교에서 `greatest`가 `test`에 걸려 셸 도구와 다른 실행 모델을
  선택하는 추가 문제를 발견했다. 영어 도구 힌트를 단어 단위로 판별하며
  `profile/file`, `happy/app`, `archetype/type` 같은 오탐도 회귀 검사한다.
  한국어 힌트는 유지한다. 합성 회의 테스트에서 같은 선택 모델이
  풀이 2회와 최종 검증 1회를 담당하고 실행 모델로 전환하지 않음을 확인했다.

실험적 필드를 사용하려면 초기화에서 명시적으로 기능을 협상해야 한다는
[공식 App Server 규격](https://learn.chatgpt.com/docs/app-server#experimental-api-opt-in)을
따른다. 이 협상은 계정의 Daybreak 사용 자격이나 PC 권한을 부여하지 않는다.

## 검증

- 실제 설치된 CLI + 합성 localhost 공급자에서, 수정 전 기능 협상 오류를
  재현했다. 계정 요청이나 모델 사용량 없이 실행한 테스트다.
- 수정 후 새 대화, 같은 세션의 후속 대화, 프로세스 재시작 후 복원이 통과했다.
- 네이티브 테스트 서버에도 같은 기능 협상 검사를 넣어 회귀를 잡는다.
- 관련 자동 테스트 22개, 네이티브 오케스트레이션 테스트 16개,
  세션 재사용/취소/권한 경계 및 이벤트 순서 테스트가 통과했다.
- 에이전트·웹·모바일 TypeScript 검사와 Windows 설치 파일 빌드가 통과했다.

이번 핫픽스 배포 대상은 PC 에이전트·데스크톱/웹 패키지다. 모바일 소스의
버전은 0.6.1로 유지했으며 0.6.2 APK를 만들었다고 주장하지 않는다.
