# Mr.Robot 0.6.14 작업 흐름과 협업 안정성 개선

작업을 중지하거나 대화를 전환할 때 실행 상태가 엇갈리는 문제와, 긴 협업 요청에서 원문이 잘리던 문제를 수정했습니다. 이번 변경은 실행 안정성과 사용 편의를 위한 것이며 모델 자체의 정답률 향상을 주장하지 않습니다. 기존 모델 선택, 권한, 기본 협업 프리셋은 자동 변경하지 않습니다.

## 작업 중지와 대화 전환

- PC와 모바일은 중지 요청의 수신 확인과 실제 작업 종료를 구분합니다. 종료 이벤트가 늦으면 실행 목록을 재확인하며, 네트워크 오류를 작업 종료로 취급하지 않습니다.
- 이전 요청의 늦은 RPC 응답이나 오류가 다음 요청을 완료 처리하거나 다른 대화에 오류를 표시하지 않도록 요청 소유권을 확인합니다.
- 응답 연결에 문제가 생겨도 PC 작업이 계속 실행 중이면 그 사실을 안내합니다. 실행 여부가 불명확한 요청을 자동으로 재전송하지 않습니다.
- 모바일에서 대화를 바꾸면 작성 중인 문장을 대화별로 보관합니다. 이는 현재 화면 수명 동안 최대 30개 대화의 임시 보관이며 앱 재시작 이후의 영구 저장은 아닙니다.
- 작업 종료 후 남은 승인 창을 정리하고, 모바일은 종료 이벤트 없이 최종 RPC 응답만 도착해도 응답을 표시합니다.

## 모델 선택과 협업 문맥

- 실제 설치 앱 검사에서 짧은 요청을 참고 데이터처럼 해석해 “요청이 없다”고 답하는 실패를 확인했습니다. Codex 텍스트·브로커 전송에 현재 사용자 요청, 이전 기록, 도구 관찰을 구분하는 봉투 형식을 적용했습니다. 원본 대화와 증거의 내용은 변경하지 않으며, 파일에 적힌 역할 이름을 지시로 승격하지 않습니다.
- 적응형 API 모델도 명확한 인사에는 같은 모델의 낮은 추론을 사용하고 불필요한 플러그인·보조 도구를 싣지 않습니다. 입력 안에 있는 글의 요약·번역은 네이티브 PC 실행 없이 처리하되 사용자가 선택한 추론 수준은 유지합니다.
- 적응형 모드에서 고비용 호출 한도에 도달하면 명확히 중단합니다. 선택한 주 모델을 임의의 무료 모델로 대체하지 않습니다. 기존 비적응형 모드의 명시적 비용 절약 전환 정책은 유지합니다.
- 적응형 주 모델이 현재 연결에서 도구를 지원하지 않으면 다른 실행 모델을 몰래 연결하지 않고 설정 안내를 표시합니다.
- API 방식의 적응형 보조 작업이 마지막 주 모델 응답에 필요한 유료 호출까지 소진하지 않도록 한 회를 남깁니다. 여러 도구 단계에 필요한 모든 호출을 무조건 보장한다는 뜻은 아닙니다.
- 회의형, 혼합형, CTF 스웜에서 원래 요청과 프로젝트 지시를 통째로 꼬리 자르던 처리를 제거했습니다. 중복된 보조 의견은 별도로 제한하고, 생략된 제안은 불완전한 자료임을 표시합니다. 공급자 자체의 문맥 한도를 없애는 변경은 아닙니다.
- 적응형 보조 실행이 현재 격리·예산·연결 조건에서 가능한지 진행 기록에 표시합니다. 보조 작업에 PC 전체 권한을 추가하지 않습니다.

중지의 수신 확인과 최종 상태를 구분하는 방식은 [공식 Codex App Server의 실행 수명주기](https://learn.chatgpt.com/docs/app-server#lifecycle-overview)를 참고했습니다. 실제 권한, 실행 소유권, 상태 확인은 Mr.Robot의 기존 호스트 경계 안에서 처리합니다.

## Docker 경로 재검증

전체 회귀 검사의 폴더 교체 감지 테스트가 한 번 실패했습니다. 파일 식별자를 일반 숫자로 저장하던 부분을 확인하고, 64비트 정밀도를 유지하는 BigInt 기반 문자열과 생성 시각으로 비교하도록 수정했습니다. 실제 식별자의 정밀도 보존, 인접 식별자 구분, 변경되지 않은 폴더 허용, 같은 경로의 교체 차단을 검사합니다. 경로 재검증과 Docker 마운트 사이의 모든 파일시스템 경쟁 조건을 완전히 없앴다는 주장은 아닙니다.

같은 식별자 비교를 사용하는 프로젝트 지식·AGENTS.md·근거 파일 읽기와 다운로드 검사도 정밀도를 보존하도록 맞췄습니다. 모바일 암호화 파일 다운로드는 읽기 전에 확인한 파일과 실제 열린 파일을 비교합니다. 전송 버전 형식이 바뀌므로 업데이트 중 진행하던 파일 다운로드는 다시 시작해야 할 수 있습니다.

## 검증 범위

적응형·문맥 회귀 테스트와 4개 요청 수명주기 테스트를 추가했습니다. 별도의 PC 화면 재현 검사에서 6.5초 지연되는 중지, 4초 늦게 도착하는 이전 성공 응답과 실패 응답을 확인했습니다. 7개 화면 크기에서 프로젝트·전송·중지·레이아웃을, 모델 선택과 캘린더 화면도 별도 검사했습니다.

전체 `npm test`, PC·모바일 타입 검사, 암호화 파일 전송·권한 경계 검사, 네이티브 창의 강제 렌더러 종료 후 복구 검사가 통과했습니다. 모바일의 추가 중지 상태 정리는 별도 UI 계약·타입 검사로 재확인했습니다.

2026-10-03에 설치된 Windows 0.6.14의 인증된 `chat.start` 경로로 `gpt-6-sol`, 높은 추론을 고정해 다음 5개 흐름을 확인했습니다. 짧은 값 추출 4.659초, 같은 대화의 값 기억 2.278초, 임시 프로젝트 파일 읽기 6.746초, 실행 등록 직후 취소 0.120초, 취소 후 새 요청 2.946초였습니다. 네 번의 답변은 기대값·저장된 답변·실시간 출력이 일치했고, 취소는 취소 이벤트와 실패 반환을 확인했습니다. 장시간 도구 실행 도중의 취소를 실측한 것은 아닙니다.

처음 실패한 결과와 수정 후 결과는 별도로 보존했습니다. 소규모 기능 확인이며 공식 성능 점수, 일반적인 속도 향상률, 어려운 문제의 정확도 향상으로 해석하지 않습니다. 기존 모델·협업 설정·플러그인 활성 상태·메모리 목록은 유지됐고 검사 종료 후 실행 중인 작업은 0개였습니다.

Windows 설치본의 `app.asar`가 최종 빌드와 일치함을 SHA-256으로 확인했습니다: `1B1BCDABEE5E3002FB6F79C26B7AE893C9D170EFDBE4B475246EDA507342870F`. 설치 파일은 코드 서명이 없는 자체 빌드입니다.

Android 실제 기기의 키보드 동작과 네트워크 단절 후 복구는 이번 화면 검사로 입증되지 않습니다. 전체 앱에 오류가 없거나 보안이 완벽하다는 의미도 아닙니다. Git 소스 푸시와 GitHub Release 설치 파일 게시, APK 배포는 별도 작업입니다.
